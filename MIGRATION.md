# Перевод проектов на mishka-ds

Пакет собран из четырёх репозиториев, но пока ни один из них его не потребляет: там лежат копии, а копии расходятся. Это уже произошло — конфиги mermaid в `jtprog.ru` остались в палитре 0.1, пока весь блог переехал на 0.2, а `--fg-subtle` на тёмной теме годами валил AA, потому что проверяли только светлую.

Порядок ниже составлен так, чтобы каждый проект переезжал независимо и ни один шаг не ломал прод.

## Общее для всех

Токены теперь называются по `BRANDING.md`: `--fg`, `--bg-elev`, `--border`. Старые имена всех трёх проектов (`--text`, `--bg-elevated`, `--rule`, `--link`, `--callout-note`, `--font-text` …) продолжают работать через `compat.css` — он входит в `styles.css` и ничего не объявляет сам, только ссылается на канонические.

Значит, порядок такой: сначала подключить пакет и убедиться, что ничего не изменилось, и только потом, когда удобно, переписать локальные имена на канонические и выкинуть `compat.css` из импорта.

Три значения изменились по существу, и это осознанно:

- `--accent-600` на светлой теме затемнён с `#209fb5` до `#1c8a9d`. Старое значение давало 2.78:1 и не проходило даже AA large, хотя `BRANDING.md` разрешал им набирать крупный текст.
- `--fg-subtle` на тёмной теме поднят с `#8087a2` до `#939ab7` (overlay2). Старое давало 4.14:1 — ниже AA.
- `--font-sans` — IBM Plex Sans вместо Onest. У Onest нет курсивного начертания, поэтому `em`, цитаты и любой выделенный курсивом текст браузер наклонял синтетикой. Это единственная правка из трёх, которую видно сразу: метрики другие, строки в колонке перенесутся иначе. Сверять надо страницы с длинной прозой, а не только главную.

Первые два места визуально почти не меняются, но перестают быть нарушением.

## hugo-mishka (блог)

Перед началом: `make serve` в `jtprog.ru` не запускать одновременно с прод-сборкой, иначе `public/` затирается продовым `baseURL`.

1. Подключить пакет — submodule в `vendor/mishka-ds` либо npm-зависимость, если у темы появится `package.json`.
2. `assets/css/modules/00-vars.css` заменить на `@import` токенов и `compat.css`. Проверить переключатель тем и `prefers-contrast: more` — этот блок легко потерять.
3. `02-fonts.css` заменить на `fonts-hugo.css` из пакета: там абсолютные пути `/fonts/...`, как требует `resources.Concat`. Заодно появляется self-hosted Iosevka, которой в теме не было вообще — моноширинный был объявлен в `--font-mono`, но не хостился, и код показывался системным SF Mono.
4. Модули `03-page-header`, `06-profile`, `07-post-card`, `08-post-single`, `10-callouts`, `11-code`, `13-kbd`, `14-footnotes`, `15-tags`, `17-mermaid`, `30-related`, `35-post-endnote` заменить на `components.css`. Имена классов совпадают один-в-один, шаблоны править не нужно.
5. Сверять постранично, а не по главной: пост с кодом и врезками, список постов, проекты, облако тегов, 404.

В теме остаются `04-header`, `05-footer`, `09-toc`, `12-chroma`, `16-search`, `18-math`, `19-archive`, `20-404`, `31-post-actions`, `32-edit-post`, `33-translation`, `34-reading-mode`, `99-a11y`. Это Hugo-специфика и генерируемые файлы.

`95-print.css` можно удалить: его роль берёт `print.css` пакета.

## jtprog.ru (контент блога)

Заменить `scripts/mermaid-config.json` и `scripts/mermaid-config.dark.json` на сгенерированные `dist/mermaid/*`, затем перегенерить SVG в `assets/mermaid/`. Без перегенерации старые схемы останутся в тёплой палитре, новые появятся в холодной, и пост будет выглядеть собранным из двух блогов.

## savinmi.ru (резюме, Astro)

1. `bun add @jtprogru/mishka-ds` (или путь к локальному пакету на время).
2. В `src/styles/global.css` удалить весь блок `:root` / `[data-theme]` и вместо него импортировать `@jtprogru/mishka-ds/styles.css`. Локальные имена (`--fg`, `--rule`, `--link`, `--callout-*`, `--font-text`, `--font-code`) продолжают работать через `compat.css`.
3. Убрать зависимости `@fontsource/pt-sans` и `@fontsource/jetbrains-mono` — шрифты приезжают из пакета теми же сабсетами.
4. `--content-width: 740px` привести к общему `--content-width: 720px`. Расхождение историческое: 740 подбиралось под перенос меню, а не под читаемость. Если меню действительно ломается — чинить меню, а не ширину колонки.
5. Заголовки сейчас заданы своими значениями (`1.85rem`, `1.4rem`, `1.15rem`) мимо шкалы. Перевести на `--fs-*`: ближайшие ступени — `--fs-2xl`, `--fs-xl`, `--fs-md`.
6. Для печати резюме подключить `print.css` и обернуть страницу в `.sheet`, если нужен настоящий A4-макет, а не браузерная печать «как есть».

## slidev-theme-bear (презентации)

1. Добавить `@jtprogru/mishka-ds` в зависимости.
2. `styles/vars.css` удалить целиком, вместо него импортировать `@jtprogru/mishka-ds/styles/tokens.css`, `themes-scoped.css` и `compat.css` в `styles/index.ts`. Slidev переключает тему классом `html.dark` — этот селектор есть в сгенерированном `themes-scoped.css`, отдельный мост не нужен.
3. `uno.config.ts` свести к импорту готового пресета:

   ```ts
   import { defineConfig } from 'unocss'
   import { theme, shortcuts } from '@jtprogru/mishka-ds/unocss'

   export default defineConfig({ theme, shortcuts })
   ```

   Заодно в утилитах появляются `text-chart-1…8`, которых в теме не было.
4. Импорты `@fontsource/*` убрать — шрифты в пакете.
5. `scripts/check-contrast.mjs` удалить: его роль берёт `npm run contrast` пакета, и проверяет он теперь все поверхности разом, а не только слайды. Именно расширенная версия и нашла две дырки, описанные выше.
6. Крупные кегли в `layout.css` (`text-6xl`, `text-8xl`) заменить на display-ступени: `var(--fs-display-sm)` и `var(--fs-display-lg)`.
7. Плейсхолдеры `public/mark.svg`, `logo.svg`, `mascot.svg` заменить ссылками на `brand/*` пакета — иначе в презентациях останется янтарный медведь из палитры 0.1.

## Признак, что миграция удалась

Контрасты зелёные во всех проектах одной командой. Изменение цвета в `tokens.css` доезжает до блога, резюме, слайдов и схем без ручного копирования. Ни в одном репозитории не осталось объявления `--accent-*`, `--bg`, `--fg` — только использование.
