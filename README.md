# mishka-ds

Дизайн-система «Мишка на сервере». Один источник цвета, шрифтов, ритма и правил для всего, что выходит под этим именем: блога [jtprog.ru](https://jtprog.ru), резюме [savinmi.ru](https://savinmi.ru), презентаций на `slidev-theme-bear`, схем в постах и печатной продукции.

Система не придумана заново — она собрана из четырёх репозиториев, где одно и то же жило четырьмя копиями. Одна и та же роль называлась `--text` в теме блога, `--fg` в слайдах и резюме, `--rule` вместо `--border` в третьем месте; шрифты подключались тремя разными способами; контрасты проверялись только в презентациях. Копии успели разойтись: конфиги mermaid в блоге остались в палитре, от которой бренд ушёл год назад.

Скиллы, которые опираются на систему (сборка докладов и прочее), — в [skills/](skills/README.md).

Большая картинка — как работать с брендом во всех ипостасях, от favicon до конференц-слайда и визитки — в [BRAND.md](BRAND.md). Порядок перевода проектов — в [MIGRATION.md](MIGRATION.md).

## Слои

| Слой | Файл | Кто потребляет |
|---|---|---|
| Токены | `src/styles/tokens.css` | всё |
| Темы для любого узла и для `html.dark` | `themes-scoped.css` (генерится) | превью, Slidev |
| Старые имена токенов | `compat.css` | блог, резюме, слайды — до миграции |
| Шрифты | `fonts.css` + `fonts/` | всё |
| База: reset, типографика, каркас, a11y | `base.css` | web-поверхности |
| Компоненты | `components.css` | блог и React |
| Подсветка синтаксиса | `code.css` | React, где код красит `highlight.js` |
| Печать: A4, визитка, `@media print` | `print.css` | резюме, визитки, раздатка |

React-компоненты собственных стилей не имеют: они выводят те же классы, что и Go-шаблоны темы (`.callout--warn`, `.post-card__title`), поэтому одна таблица обслуживает и сайт, и превью, и дизайн-агента.

## Установка

```bash
make install    # npm ci при наличии лока, иначе npm install
make build      # dist/, tokens.json, mermaid, unocss + проверка контрастов
make demo       # витрина на http://localhost:4321/demo/, следит за исходниками
make check      # css + typecheck + contrast, без сборки
make help       # весь список
```

Makefile — обёртка над `scripts/*.mjs` для того, кто пакет разрабатывает. Npm-скрипты остались на месте и делают то же самое: `npm run build`, `npm run demo`, `npm run contrast`, `npm run typecheck`. Отдельными целями вынесено то, чего в npm-скриптах не было: `make css` — структурная проверка стилей, `make mark` — пересборка знака из артворка, `make fonts` — нарезка сабсетов (нужен `pyftsubset`, поэтому шаг ручной), `make skills-link` — симлинк `skills/*` в `~/.claude/skills`.

Витрина показывает обе темы рядом; `#light` или `#dark` в адресе оставляет одну. Макет визитки — `brand/card.html`, печатается прямо из браузера.

`make demo` не только собирает и поднимает сервер, но и следит за `src/`, `demo/`, `brand/`, `tokens/` и `scripts/`: правка исходника пересобирает пакет, открытая вкладка перезагружается сама. Без слежения — `make serve`.

## Что отдаёт пакет

```js
import '@jtprogru/mishka-ds/styles.css';          // всё
import '@jtprogru/mishka-ds/tokens.css';          // только переменные
import '@jtprogru/mishka-ds/print.css';           // бумага
import { theme, shortcuts } from '@jtprogru/mishka-ds/unocss';   // Slidev
import tokens from '@jtprogru/mishka-ds/tokens.json';            // инструменты
```

Плюс `dist/mermaid/*.json` для схем, `dist/brand/*` для знака и маскота, `dist/styles/fonts-hugo.css` для Hugo с абсолютными путями к шрифтам.

React:

```tsx
import '@jtprogru/mishka-ds/styles.css';
import { ThemeProvider, Callout, CodeBlock } from '@jtprogru/mishka-ds';

<ThemeProvider defaultTheme="dark">
  <Callout type="warn" title="Осторожно">
    <p>Откат деплоя приоритетнее, чем разбор root cause.</p>
  </Callout>
  <CodeBlock lang="bash" code="kubectl rollout undo deploy/api" />
</ThemeProvider>
```

Компоненты: каркас (`Container`, `Prose`, `Grid`, `PageHeader`, `SectionTitle`, `Breadcrumbs`), контент (`Callout`, `CodeBlock`, `InlineCode`, `Kbd`, `Collapse`, `Quote`, `ThinPlace`, `RefreshBanner`, `CtaCard`), карточки и пилюли (`PostCard`, `ProjectCard`, `CompactCard`, `Tag`, `Badge`), `Icon`, обвязка сайта (`SiteHeader`, `SiteFooter`, `BearMark`, `ThemeToggle`), слайды (`Deck`, `Slide`, `SlideCover`, `SlideSection`, `SlideFact`, `SlideStatement`, `SlideQuote`, `SlideBullets`, `SlideTwoCols`, `SlideOutro`) и печать (`Sheet`, `BusinessCard`). Плюс `ThemeProvider` с хуком `useTheme`.

## Всё, что генерится из токенов

Токены разбираются в `tokens/tokens.json`, и из него выводится остальное: scoped-темы, пресет UnoCSS для Slidev, темы mermaid для светлой и тёмной схемы, вариант `fonts.css` с абсолютными путями. Руками эти файлы не править — перезапишутся на сборке.

Шрифты собираются отдельным ручным шагом: `node scripts/gen-fonts.mjs` режет `@fontsource/onest` и `@fontsource/iosevka` на unicode-range сабсеты и пишет `fonts/` вместе с `fonts.css`. Нужен `pyftsubset`; результат коммитится, поэтому обычная сборка его не требует.

По той же схеме собирается знак. Источник — артворк `brand/mishka-mark-source.svg`, из него `scripts/gen-mark-geometry.mjs` делает `src/components/markGeometry.ts`, а из геометрии — `brand/mark.svg`, `brand/logo.svg`, `brand/mascot.svg` и знак внутри `brand/card.html`. Менять надо артворк, а не производные.

Смысл в том, что расхождение возможно только вместе с расхождением токенов. Именно ручное копирование mermaid-конфига в блог и привело к тому, что схемы там до сих пор рисуются в палитре 0.1 с оранжевым `#c2410c` и `fontFamily: Inter`.

## Проверка контрастов

Перед этим сборка гоняет `scripts/check-css.mjs` — структурную проверку таблиц стилей: баланс комментариев и построчный разбор `tokens.css`. Она ловит то, чего не видит проверка контраста: `tokens.json` собирается регуляркой и битый синтаксис вокруг объявления игнорирует, а браузер по правилу восстановления теряет и мусорную строку, и соседнее с ней объявление. Ровно так однажды пропал `--chart-1` в светлой теме при зелёных проверках.

`npm run contrast` считает WCAG-отношения для всех текстовых пар в обеих темах и падает, если хоть одна ниже порога. Раньше такая проверка существовала только в теме презентаций и покрывала только их палитру. Расширенная на общие токены, она сразу нашла две дырки, которые жили в проде:

- `--accent-600` `#209fb5` на светлом фоне давал 2.78:1 и не проходил даже AA large, хотя брендбук разрешал набирать им крупный текст. Затемнён до `#1c8a9d` — 3.59:1 на фоне страницы и 3.34 на карточке.
- `--fg-subtle` на тёмной теме давал 4.14:1 — ниже AA. Поднят до Macchiato overlay2 `#939ab7`, 5.29:1.

Категориальная палитра проверяется отдельно, на яркостное разделение соседних серий. Порядок восьми цветов посчитан перебором всех перестановок и максимизирует минимальное расстояние сразу в обеих темах. Потолок задаёт сама палитра: акцентные тона catppuccin лежат в узкой полосе яркости, и в тёмной теме достижимый максимум — 1.15:1. Поэтому в системе жёсткое правило — цвет в графике всегда дублируется вторым различителем.

В светлой теме четыре серии пришлось успокоить отдельно. Latte отдаёт акценты в полную силу, и Red, Green, Mauve и Peach выбивались из ряда — рядом с приглушёнными Sapphire, Lavender, Yellow и Teal они резали глаз. Хрома сведена к средней по остальным сериям в OKLCH: тон сохранён, упала только насыщенность. Разделение соседей после правки — 1.21:1, выше прежнего.

Подсветка синтаксиса проверяется теми же парами: десять ролей `--syn-*` против подложки кода, обе темы. В светлой роли catppuccin пришлось затемнить — сырой `catppuccin-latte` держит AA не везде.

## Чего система не покрывает

Своего движка подсветки в пакете нет — есть раскладка ролей. `CodeBlock` красит код через `highlight.js`, если тот доступен: передан пропом `highlight`, лежит в глобальном `hljs` или установлен как пакет. Не нашлось ничего — блок рендерит простой текст, это рабочее состояние. Цвета берутся из токенов `--syn-*` и проверяются на AA вместе с остальными парами; сам `highlight.js` объявлен опциональной peer-зависимостью и в бандл не едет.

Растровых производных знака нет: `brand/` отдаёт вектор — `mark.svg`, `logo.svg`, `mascot.svg` и два фавикона под светлый и тёмный интерфейс. Нарезка favicon 16/32, apple-touch 180 и PWA 192/512 остаётся за площадкой. Как устроен знак и почему он одноцветный — в [BRAND.md](BRAND.md#3-идентичность-знак-логотип-маскот).
