# Скиллы бренда

Скиллы, которые опираются на эту дизайн-систему и на `BRAND.md`. Лежат в пакете намеренно: правило и его исполнитель должны меняться вместе. Когда меняется брендбук, скилл правится в том же коммите, а не «когда-нибудь потом».

| Скилл | Что делает |
|---|---|
| [`mishka-deck`](mishka-deck/SKILL.md) | Собирает доклад целиком: нарратив, раскладка по лейаутам Slidev, текст авторским голосом, проверки |

## Как подключить

Claude Code ищет скиллы в `~/.claude/skills/`. Симлинк, чтобы не держать копию:

```bash
make skills-link   # из корня пакета: линкует всё, что лежит в skills/
```

Руками то же самое:

```bash
ln -s ~/Work/github/jtprogru/mishka-ds/skills/mishka-deck ~/.claude/skills/mishka-deck
```

Либо, если скиллы собираются в `bear-skills`, — симлинк оттуда сюда. Копировать не надо ни в том, ни в другом направлении: копия разойдётся, как разошлись конфиги mermaid.

## Что ещё просится

Ниша под скилл видна там, где бренд применяется руками и каждый раз чуть по-разному:

- **`mishka-onepager`** — лендинг или страница проекта из README: те же токены, компоненты `PageHeader` / `ProjectCard` / `CtaCard`.
- **`mishka-cv`** — резюме под конкретную вакансию: содержание меняется, вёрстка и печать берутся из `print.css` и `.sheet`.
- **`mishka-chart`** — график к посту: категориальная палитра, обязательная подпись у линии, экспорт в SVG под тёмную и светлую тему.

Существующий `mishka-cover` (обложки постов) написан раньше пакета и палитру знает наизусть — его стоит переписать на чтение `tokens.json`, чтобы обложки не разъехались с остальным при следующей смене версии брендбука.
